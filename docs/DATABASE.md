# Database source and preservation

This export includes schema migrations, not hosted data, database credentials, backups, sessions, user lists, or operational recovery records. The application database is a read/application model; the Solana program remains authoritative for outcomes and token custody.

Migrations are ordered by filename. The security reservation migration and versioned HTS welcome migration must both be present before enabling the new service. The HTS release registry starts empty/disabled and requires reviewed, owner-controlled activation; empty environment values do not activate it. Grant and operational SOL spending share atomic daily budgeting, including account-creation costs and unresolved holds. Direct evidence-table writes and internal reservation helper execution are restricted explicitly rather than relying on provider default grants.

The serverless recovery migration additionally requires separately approved provisioning of `pg_cron`, `pg_net`, and Vault. It is intended for a newly provisioned, dedicated `pg_net` installation with empty request/response tables, and refuses a nonempty installation. Its ACL restrictions affect the entire `net` extension schema, including table, sequence, and function access for PUBLIC and application roles; it must not be applied to an extension shared with other consumers. Inspect those dependencies and consumers before adoption. Installation creates no scheduled job and leaves recovery disabled. The bounded scheduler must be configured and activated separately with the verified Devnet-only HTTPS endpoint and a dedicated cron credential in Vault; no credential is supplied by this export.

The historical `20260929000004_admin_full_admin.sql` migration retains the complete executable role-constraint SQL. Only private operator comments were replaced. The source migration does not insert a wallet membership, and this public bootstrap grants no wallet administrator access. Existing hosted memberships are not removed, modified, or reproduced by this export.

A local Supabase configuration is intentionally not copied from private operational setup. Initialize an isolated disposable local project using the pinned CLI documentation before applying these schemas. Do not link a hosted project or run hosted reset/push commands as a local setup shortcut. Hosted adoption needs an independently verified backup/restore procedure, migration review, and owner approval.
