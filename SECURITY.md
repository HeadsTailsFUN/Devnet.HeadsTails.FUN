# Security and responsible reporting

This is Devnet test software. Use synthetic accounts and disposable local environments for testing. Do not submit exploit transactions against public deployments or access other users' accounts.

Never include wallet secrets, recovery phrases, service credentials, user records, or signed live transaction bytes in public issues. Use GitHub's private vulnerability reporting if the repository owner enables it. Otherwise arrange a private reporting channel with the verified owner; do not publish sensitive details in an issue.

The program governs outcomes and escrow; operators cannot choose ORAO randomness. Private deployment and recovery procedures are intentionally excluded. Public source availability is not deployment approval or a warranty of security. Release-specific independent review and actual-runtime verification must precede publication.
